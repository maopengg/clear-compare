# 仓库远程管理

工作区工具栏的“远程管理”展示当前仓库的远程名称，以及 Git 解析出的全部获取/推送地址。支持添加、替换首个获取或推送地址、移除仓库主配置中的独立推送地址、删除远程，以及获取/获取并清理失效跟踪引用。配置修改不自动拉取。

编辑时填写完整的新地址，不把已隐藏凭据的显示值直接写回 Git。多地址配置中，修改命令明确匹配原来的首个地址，保留其他地址；若原地址在配置中重复出现，Git 可能拒绝不唯一的修改，失败会保留配置和编辑输入。继承自全局、工作树或 include 配置的地址不在此入口改写；需要在来源配置中修改，应用不会为了修改当前仓库而覆盖共享配置。清除本仓库的推送配置后，界面重新显示 Git 实际解析的地址，不能假定一定等于获取地址。

## 检查连接

获取和推送地址各有检查入口，使用本机 Git/SSH/凭据配置执行只读 `ls-remote`，展示引用数量、远程默认分支及耗时。不会下载对象、检出或提交；成功只能证明列出引用的连接可用，不能证明推送写入权限。失败显示 Git 的连接、认证或网络错误，保留上次成功检查信息（明确标为“上次”）；选择其他远程、成功修改配置或刷新后清除旧检查结果。沿用原生命令的时间/输出限制和全局取消机制。

## 配置恢复

新增、修改、清除和删除都先进入统一确认。原生执行前复查仓库版本、目录身份和配置来源，保存并校验本仓库 `config` 原始字节，记录 SHA-256 和相关远程跟踪引用；删除远程时还捕获远程跟踪引用集合，覆盖自定义 fetch 目标命名空间；对应提交会保存到独立的恢复引用，避免删除远程后仅剩一份无法阻止 Git 清理的对象编号。

恢复材料位于 Git 公共元数据目录下的 `clear-compare-remote-backups/<操作标识>/`：

- `config`：修改前的主配置原文，可能含原有凭据，不写入 Git 对象库。
- `before.json`：配置摘要及原跟踪引用与恢复引用的对应关系。
- `result.json`：远程命令的成功/失败结果；不存在不等于未执行，需核对当前 Git 状态。

Unix 上新建目录/文件采用 0700/0600 并同步目录元数据；其他系统沿用父目录权限规则。备份文件写入后同步并读回校验，拒绝通过符号链接的配置或备份目录写入。成功结果在操作日志中显示恢复目录，命令失败也会返回恢复位置。后续恢复必须核对当前配置和引用，不能直接用旧配置覆盖后来修改；图形化恢复入口尚未实现。

## 确认上下文

正常切换仓库会取消旧的待确认计划，执行前还会核对当前页面仓库与计划仓库。界面对写操作的完成结果按操作序号关联：如果另一个 Git 操作替换了原确认，原配置/分支/Stash 草稿不会被误当成已保存而清空。确认取消和实际失败仍保留原输入。

## 地址显示与分组

标准 URL 的用户信息、查询参数和片段从地址显示、确认命令及缓存分组标识中移除或隐藏。原始配置仍由 Git 使用，填写的新值由 Git 保存。普通 SSH/HTTPS 地址按主机/路径匹配，适用的默认端口归一；修改后更新当前仓库的匹配标识，用户无需重扫整个目录。显示的隐藏地址用于识别，不能用作完整配置值。

## 验证边界

`workbench_remotes` 在临时仓库和本地 bare 远程中验证独立获取/推送配置、多地址保留、清除独立推送配置、配置/对象恢复材料、凭据隐藏、过期计划、配置锁失败、继承配置保护、只读连接检查及符号链接备份路径拒绝。

`scripts/check-git-remotes.cjs` 使用真实 WASM 与模拟 IPC 验证地址展示/重绘、明确的新地址输入、确认取消、失败输入保留、获取/推送独立修改、清除/新增/删除、连接失败、获取并清理、刷新失败、空状态、跨视图保留草稿、语言和布局。模拟 IPC 不能证明真实桌面 Git/凭据集成；三系统运行和安装验收仍待进行。逐个管理附加地址、来源配置编辑及恢复材料 GUI 仍属于后续完善范围。
