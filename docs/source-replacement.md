# 跨文件替换

入口位于“文件 / 全局搜索”搜索栏下方的折叠区。设置上方查询和范围，输入替换内容（空内容表示删除匹配），点击“预览批量替换”。预览不写源文件，选择具体文件查看统一差异，再执行所选文件。每个计划只能执行一次；失败或取消后须重新预览。

## 范围与匹配

- 与普通正文搜索共享当前文件、当前仓库、当前目录、全部收录仓库范围和原生文件 ID。没有当前标签时，“当前文件”不会退化为整个仓库。
- 共享大小写、全词、正则、多行、包含/排除规则、项目排除和 `.gitignore` 策略。仅支持正文替换；名称和路径查询不开放替换。
- 字面替换不展开美元符号；正则支持 `$1`、`${name}` 和 `$$`，未知或未闭合引用在扫描前拒绝。按 LF 归一化后的文本匹配，再按原编码、BOM、换行格式写回；混合换行必须明确选择 LF/CRLF/CR。
- 普通搜索的每文件 200 条展示上限不用于替换：原生层收集命中文件后重新验证摘要，计算该文件全部匹配。单文件最多 20 万处匹配，超过则拒绝整个预览，不截取后静默执行。
- 扫描最多 5000 个命中文件、250000 个候选文件，并受 60 秒预算和 Git 命令限制。扫描取消或截断会拒绝预览，要求缩小范围。大于 4 MiB、二进制和不可读文件计入跳过；警告和跳过数量显示在预览里。不能把已搜索文本范围当作所有文件均可编辑。
- 替换内容最多 65536 字节，单文件保留既有 4 MiB 编码字节/8 MiB 解码正文限制。计划持有的原文和新文合计最多 64 MiB。文件列表每页 200 项，差异每页 500 行，超长行只显示前 8192 字符并明确提示；分页不缩小实际替换范围。

## 保存保护和恢复证据

未保存源标签、Git 冲突、只读文件、需要确认的混合换行和实际内容不变项显示原因且不可选择。UI 与原生层分别检查未保存状态。

执行前复查所选仓库状态、文件规则、根目录/文件/父目录身份和原始内容摘要。首次写入前完成所有所选文件的复查，随后每文件写入前再次核对身份、摘要和草稿。时间戳相同不能代替内容复查。符号链接替换、父目录替换或外部正文变化会阻止写入。

每次操作在应用数据目录 `source-replacements/<plan-id>` 创建私有恢复目录：

- `intent.json`：不可覆盖的计划、所选条目、原生路径、原始/预期摘要与备份映射。
- `NNNN-before.json` / `NNNN-after.json`：逐文件执行前后记录。
- `files/<entry-id>/<save-id>/`：复用文本保存的原始字节、格式/权限及状态清单；备份校验后原子替换目标，验证新摘要，刷新目录元数据。
- `result.json`：状态、已尝试文件及错误；不复制打开编辑器的完整正文到结果日志。

进度在预览底部按已处理文件/总数及路径更新。取消在文件之间生效；单个文件的备份、替换和验证不能在中间强行打断。完成项保留，后续未执行项明确显示；外部修改、保存/日志失败也保留已完成项和恢复证据，不自动回滚或重试。日志路径在结果中显示。异常退出时可能只有 intent/逐文件记录，应结合文件摘要和保存清单检查实际现场。

已打开且没有草稿的标签按原文核对后接收保存结果，保留标签身份与撤销历史。任务期间仍禁止用户编辑，刷新不会通过临时解除只读来写入；若编辑器内容不再匹配则保留该内容并标记外部变化。批量替换预览里 ⌘S/Ctrl+S 不触发底层编辑器保存，焦点和 Tab/Shift+Tab 限制在弹窗内。

## 验证与边界

`workbench_replace` 使用独立临时 Git 仓库验证真实磁盘字节、全部匹配、UTF-16/BOM/CRLF、分组/零宽正则与扩展大小限制、范围/规则、冲突/只读/草稿、过期计划、相同时间戳下的外部修改、符号链接替换、取消/部分完成、干净标签的新保存基线及恢复材料。

`scripts/check-source-replacement.cjs` 使用真实发布 WASM 和 CodeMirror、模拟原生计划，验证共享查询、原生 ID/选择、分页差异、失败保留、干净标签更新、只执行一次、进度取消、焦点/快捷键、双语和紧凑布局。模拟 IPC 不作为原生磁盘写入或系统窗口运行证据。

尚无批量替换专用恢复浏览器、一键整批撤销、跨重启续跑或非 Git 根目录。已打开但有草稿的文件不会在草稿中批量替换；请使用当前文件编辑器，或保存后重新预览。底层系统/Git/正则库的未知错误保留原始诊断。三系统完整安装与运行验收仍待完成。
