# 跨平台文件比较工具完整开发计划

版本：1.2  
日期：2026年10月14日  
状态：实施前计划  
技术栈：Rust、Tauri 2、Leptos、WebAssembly  
目标平台：Windows、macOS、Linux

实现一款以 Beyond Compare 5 为功能参考的独立桌面比较工具，支持本地与远程文件比较、文本合并和目录同步。先交付可安全完成项目代码同步的版本，再逐步覆盖高级比较、远程存储和平台集成。界面、品牌与实现由本项目独立设计。

产品名称为 Clear Compare，代码目录为 `<checkout>/clear-compare`，公开仓库为 [maopengg/clear-compare](https://github.com/maopengg/clear-compare)。分发方式在项目启动时确定。本计划不执行此前两个项目之间的同步；仓库已创建并克隆，尚未生成应用骨架。本次技术栈修订同时准备Rust工具链。

## 1 项目目标与完成定义

第一阶段业务目标：比较 `/example/source-project` 与 `/example/target-project`，导入用户提供的排除规则，预览差异与同步动作，选择文件后执行，并能够从覆盖备份恢复。

长期目标：按 Beyond Compare 5 Standard 与 Pro 的可验证能力建立逐项对照表。功能范围参考[官方功能清单](https://www.scootersoftware.com/kb/feature_compare)，验收时冻结参考版本和平台，不把未来新增功能自动纳入当前版本。

“全部功能完成”必须同时满足：

- 冻结后的每条功能有对应实现、适用平台、测试案例和结果。
- 所有适用功能经过对应平台验证；平台特有功能单独验收。
- 每种文件格式、压缩格式、协议、认证方式有明确支持列表。
- 未实现、依赖外部工具、无法验证的项目单独列出，不能计入完成。
- 没有已知的文件丢失、错误覆盖或未解决合并冲突被静默保存的问题。
- 安装、升级、卸载和用户配置迁移通过发布验证。

文件内容比较与元数据比较分别计数；无法读取、未比较、规则忽略和确定一致必须是不同状态。

## 3 技术架构

### 3.1 进程职责

Leptos负责界面与编辑交互，使用Rust编写，以CSR模式编译为WebAssembly并运行于系统WebView。原生Rust核心负责文件系统访问、规则匹配、扫描、内容比较、合并、同步、备份、远程连接与持久化；Tauri负责窗口、系统集成和前后端IPC。使用Trunk构建界面，使用Cargo工具链构建桌面与CLI，不将Node.js、npm或TypeScript作为项目必需项。WebAssembly加载器及必要的浏览器/Tauri互操作仍包含生成的JavaScript，不承诺安装包中没有JavaScript。

依据Tauri的[进程模型](https://v2.tauri.app/concept/process-model/)，界面与Rust核心通过明确的命令契约交互。普通命令返回任务句柄或小型结果；目录及diff数据分页获取，任务进度通过有界通道发送。CPU密集任务使用受限工作线程池，阻塞I/O放入受限阻塞任务；不在UI线程或异步执行器上直接运行长时间计算。外部转换器按需作为独立子进程运行，记录退出状态并支持超时和取消。

权限依据[Capabilities](https://v2.tauri.app/security/capabilities/)配置，并配合CSP限制界面来源；自定义Rust命令独立校验任务归属、路径与写入计划。Capabilities不是任意Rust文件访问的自动沙箱。前端不暴露通用文件读写或任意shell调用；文件、HTML及报告内容按不可信输入处理。

```text
系统WebView中的Leptos工作区（Rust → WebAssembly）
    ↕ Tauri命令、任务句柄、分页数据、进度通道
Tauri与Rust核心
    ├─ 窗口、菜单、对话框、系统集成
    ├─ 会话、配置、任务调度
    └─ 受限后台任务与工作线程
         ├─ 文件系统适配器
         ├─ 扫描与规则引擎
         ├─ 文本/二进制/图片/表格比较
         ├─ 合并与同步执行器
         └─ 远程连接、压缩、格式转换
```

### 3.2 核心数据与接口

- FileEntry：路径、类型、大小、时间、链接信息、可用属性、读取错误。
- CompareResult：状态、判定依据、差异摘要、证据版本、规则版本。
- CompareSession：左右路径、可选基线/输出路径、规则、视图、运行状态。
- OperationPlan：待执行动作、前置条件、冲突、删除清单、备份位置。
- OperationJournal：每个动作的开始/完成/失败状态、旧新摘要、恢复信息。
- FileSystemAdapter：Rust trait，提供列表、stat、分块读写、重命名、删除与能力声明。

共享契约放在独立的Rust contracts crate，通过serde序列化，供Leptos WASM与原生Rust核心共同引用；该crate不依赖原生文件系统或桌面运行时。Leptos通过wasm-bindgen等互操作层调用Tauri命令，对IPC返回数据执行类型化反序列化和业务校验。原生路径在Rust侧保存，不能依赖有损UTF-8转换；传给前端的是显示路径和不透明条目ID。文件大小、偏移和时间使用明确的序列化表示，避免JavaScript整数精度损失。CLI直接调用共享Rust核心，不复制一套业务实现。

远程和压缩适配器必须声明是否支持原子替换、时间精度、权限与可恢复写入，不把本地文件系统的能力直接套用到所有后端。

```text

tests/integration/     文件操作与平台集成
tests/e2e/             用户流程
benchmarks/            固定规模数据集和测量脚本

```

P0验证Tauri 2与Leptos CSR集成、Trunk构建、Rust共享契约、轻量虚拟目录树和文本差异视图；原生Rust侧评估diff/merge、编码、图片、表格、压缩及协议库。Tokio、Rayon、serde等作为任务运行和契约的候选，先验证取消、并发预算和跨端支持，再固定依赖。首版文本视图以Leptos组件实现；编辑器重点验证中文输入法、选区、撤销与大文件，必要的第三方JavaScript编辑器互操作作为独立选型决策，不直接沿用Vue组件。工作区保持Cargo.lock，确认工具链版本、依赖许可与更新策略。

采用[Leptos官方的CSR与Trunk路线](https://book.leptos.dev/getting_started/index.html)；生成静态资源供Tauri加载，不引入SSR服务、Node服务或Leptos server functions处理桌面文件操作。文件操作通过Tauri命令进入原生核心。参考[Tauri Leptos集成指南](https://v2.tauri.app/start/frontend/leptos/)，但该页面示例注明面向Leptos 0.6，P0按实际选择的版本验证配置与API。

开发前置条件依据[Tauri官方说明](https://v2.tauri.app/start/prerequisites/)：macOS需要Apple开发工具，Windows需要相应C++构建工具与WebView2，Linux需要对应发行版的WebKitGTK等依赖。Rust由rustup管理stable工具链，配备cargo、rustfmt和clippy；P0确定项目的具体版本与最低Rust版本。原生工具链安装本机目标；Leptos界面还需wasm32-unknown-unknown目标与Trunk，初始化骨架时安装并固定版本；其他架构在对应构建环境准备。

## 4 比较与写入正确性

同步流程固定为：扫描 → 比较 → 生成动作计划 → 用户检查 → 执行前重新验证 → 备份 → 写入 → 校验 → 记录结果。

- 首版默认保留目标独有文件；镜像删除属于单独模式，并显示完整删除清单。
- 排除规则在扫描、计划和执行三个阶段一致生效，受排除路径不会因父目录操作被间接删除。
- 文件在扫描后被外部修改时，停止该动作并重新比较，不能继续使用旧结果。
- 本地写入优先采用同目录临时文件加替换；跨卷移动采用复制、校验、再删除源的流程。
- 备份失败、空间不足、权限不足、文件锁定必须产生明确结果；批量任务不是跨文件系统事务。
- 每个动作写入持久日志。崩溃后报告已完成与未完成动作，恢复前重新验证路径及摘要。
- 符号链接默认不跟随；跟随时检测循环、越界和重复目标。源目标重叠路径需拒绝或进入明确受限模式。
- 文件内容比较可以忽略语义差异，但写入始终使用用户选择的原文或显式合并结果。
- 删除恢复依赖备份/回收机制；不能承诺所有远程或外部覆盖均可撤销。

## 6 第一阶段项目同步验收

源：`/example/source-project`。目标：`/example/target-project`。真实目录默认只读分析；写入验收使用其受控样本或临时副本，实际项目同步另行执行。

导入以下原始规则，分号为分隔符，前导减号表示排除：

```text
-.DS_Store;-.gitlab-ci.yml;-package-lock.json;-database.json;-env_overrides.py;-README.md;-./.git/;-./.skill/;-./docs/;-./mango-console/docs/;-./mango-console/node_modules/;-./MangoActuator/.idea/;-./MangoActuator/.venv/;-./MangoServer/.idea/;-./MangoServer/.venv/;-./MangoServer/mango_pytest/;-./MangoServer/upload/;-./MangoServer/tests/;-./MangoServer/logs/;-__pycache__/;-./mango-console/dist/;-./MangoServer/monitoring_scripts/;-./MangoServer/mango-file/;-./.idea/
```

初始解释：裸文件名与 `__pycache__/` 在任意层级匹配；`./` 从项目根匹配；尾部斜杠匹配目录及子树；`.skill/` 与 `skill/` 不等价。规则编辑器提供命中示例与预览，先核对这种解释是否符合用户原始工具的语义。

验收案例：

1. 左右相同文件、内容不同但大小时间相同、仅一侧存在、无法读取分别展示。
2. 嵌套README、缓存目录、根docs与非根同名目录按规则区分。
3. 源改动、目标已有改动、源目标目录重叠和大小写冲突均可解释。
4. 默认保留目标独有文件；`.env`作为普通差异文件明确显示，用户选择后才纳入写入。
5. 区分“磁盘全部文件”和“仅Git跟踪文件”两个可选模式，不自动排除新增产物。
6. 覆盖后可从备份恢复；备份失败时不覆盖。
7. 操作前后对排除文件计算摘要，确认字节内容未变且未被删除。
8. 比较结果与独立扫描校验一致；此前差异数量只是历史快照，每次重新计算。

## 7 内存与性能计划

以下为拟定验收预算，不是当前性能结果。P0在16GB内存参考机器上测量可行性，并确定CPU、磁盘、缓存状态、文件分布和每个平台的参考机器。

| 场景 | 初始预算 | 测量与处理 |
|---|---|---|
| 空闲单窗口 | 暂定全应用及相关WebView进程RSS合计不超过200MiB | 区分RSS、共享内存与WebView归属，三端分别测量；P0校准 |
| 10万项目录比较 | 暂定峰值不超过600MiB | Rust保存索引，分页结果、树虚拟化、缓存上限、低并发扫描；P0校准 |
| 1GiB文本/二进制 | 分块查看；完整文本diff可限制或降级 | 展示阈值和降级原因，不静默标成相同 |
| 大任务运行中 | 窗口与取消操作保持可响应 | 记录输入延迟，取消请求1秒内得到反馈 |
| 反复打开关闭20个会话 | 静置后无持续增长趋势 | 检查进程、监听器、编辑器和缓存释放 |

扫描速度、文本diff时间和复制吞吐的具体门槛在P0基准建立后确定。元数据扫描与全内容读取分别测量，不能混用速度指标。

实施规则：单主窗口内标签页共享WebView；非活动比较视图释放大对象；完整文件和目录树保留于Rust核心，不整体序列化到Leptos WASM界面；采用分页、分块与背压；磁盘、网络、CPU任务分别设置并发上限，并限制总线程预算；对代价高的diff设工作量上限与取消点。Tauri使用系统WebView，实际内存以测量结果为准，不以安装包大小推断运行内存。

## 8 REA分析计划

参考应用基线为 Beyond Compare 5。包清单检查不能证明行为或算法一致；深入分析需另有明确的证据与授权目标。

P0先通过界面观察与合成样本建立行为案例，再按需要用REA分析特定模块。每次分析记录版本、目标摘要、问题、观察结果、推断、未知项和对应测试。原生深入分析需要可用的Hopper/Ghidra/IDA；当前没有配置这些引擎，不能将反编译作为已具备能力。

重点问题：规则匹配语义、目录状态聚合、行对齐与重要差异、同步动作生成、外部修改处理、合并冲突与会话恢复。Windows专项在Windows环境取证，macOS应用包不能证明Windows行为。

REA用于解决具体未知行为；可由标准算法和公开协议实现的功能直接开发。原生引擎安装、额外软件或运行环境准备按实际需要安排，不预设全部安装。

## 9 验证策略与平台矩阵

| 层次 | 验证内容 | 通过条件 |
|---|---|---|
| 核心单元测试 | Rust路径规则、比较状态、diff/merge、动作计划；Leptos状态与WASM/IPC契约 | cargo test、前端测试、金标准样本和性质测试通过 |
| 文件系统集成 | 权限、锁定、符号链接、大小写、Unicode、磁盘满 | 故障可定位且无错误覆盖 |
| 用户流程 | 打开目录、筛选、编辑、预览、同步、恢复 | 完整操作可复现，日志与实际内容一致 |
| 协议/格式 | 认证、分页、断线、包更新、转换错误 | 每项声明支持的能力有验证记录 |
| 性能与持久运行 | 固定规模、会话循环、缓存与进程回收 | 达到P0冻结预算，无未解释增长 |
| 发布 | 安装、更新、卸载、配置迁移、签名 | 每个声明支持的平台与架构均实测 |

初始架构矩阵：macOS arm64优先；macOS x64、Windows x64、Linux x64作为完整版本目标。Windows/Linux arm64作为候选扩展，P0根据用户实际需求与依赖支持决定是否纳入。具体最低OS版本和Linux发行版必须P0冻结，不能仅写“支持Linux”。

开发过程中继续执行Rust的cargo fmt、clippy和相关cargo test，以及Leptos WASM编译与协议检查。按最新实施顺序，客户端运行、安装、升级和各平台实际使用测试集中到全部计划功能实现之后；中间阶段优先开发功能，不重复运行客户端测试。最终真实WebView验证仍覆盖Tauri命令、系统对话框、剪贴板、拖放、字体与快捷键。macOS桌面端自动化不能假定有与其他平台一致的WebDriver支持，采用原生自动化和人工验收组合。签名、系统扩展、权限提示、更新与实际安装必须在对应平台测试；交叉打包不能替代运行验收。

## 10 发布与全功能验收门槛

- 冻结的功能矩阵所有适用项目实现并验证；无法完成的条目必须重订范围，不能算作完成。
- 文件损坏、数据丢失、排除规则失效、冲突静默覆盖类问题为零。
- 所有写操作的故障注入与恢复测试通过。
- 三端性能预算、安装、更新、卸载和配置迁移通过。
- macOS正式分发完成签名/公证，Windows具备选定的签名方案，Linux包在冻结发行版验证。
- 更新包有验证机制；升级失败可回退，配置迁移先备份。
- 外部依赖、格式转换器、第三方服务要求在帮助中说明；支持范围逐项列出。
- 提供安装包、源代码、构建说明、用户手册、CLI说明、功能矩阵、测试报告和已知问题。

## 11 外部条件与主要风险

| 项目 | 影响 | 处理方式 |
|---|---|---|
| 功能范围持续扩张 | 时间无法收敛 | P0冻结基线，新功能记录到后续版本 |
| 没有Windows/Linux环境 | 无法宣称三端验证完成 | 尽早准备CI与实际测试设备/远程机器 |
| 原生分析引擎缺失 | 部分内部行为无法取证 | 优先行为测试，按需准备引擎 |
| 多种格式转换 | 结果与参考软件可能不同 | 固定转换器、版本、支持格式和限制 |
| 云账号与认证配置 | 适配无法端到端验证 | P5前确认测试账号、应用注册和测试数据 |
| 系统权限和元数据 | 三端复制语义不同 | 能力声明、专用适配器、真实平台样本 |
| WebView差异与编辑器成本 | 字体、输入法、拖放、快捷键及内存表现可能不同 | P0三端兼容与预算试验，P2前冻结编辑器方案 |
| Rust编译与依赖成本 | 首次构建、WASM/原生双目标与多架构打包增加准备工作 | 限制并行编译，优先测试核心crate，缓存依赖 |
| Leptos组件与编辑器适配 | 不能直接复用Vue组件，文本编辑与复杂目录树需要验证 | P0验证虚拟列表、中文输入和Tauri互操作，按证据调整工期 |
| 压缩/远程写入非原子 | 中断产生部分完成 | 日志、备份、校验、能力限制与恢复 |
| 签名与分发账户 | 正式发布被阻塞 | P0确认渠道，提前列出凭据与费用 |

费用不在开发周期内估算：签名/开发者账户、CI、测试机器、云存储、可选分析引擎与转换器费用在选择方案后列预算。证书与凭据由用户持有，不写入源码或普通日志。

## 12 启动清单与进度管理

启动顺序：

1. 使用已创建的Clear Compare与 `<checkout>/clear-compare` 仓库，确定分发用途。
2. 冻结参考版本、原子功能清单、三端OS与架构范围。
3. 准备三端测试条件，确认签名与远程服务的后续条件。
4. 验证Rust/Tauri骨架、命令契约、权限、目录扫描和文本编辑器的内存/性能。
5. 产出目录比较与文本差异的可交互原型。
6. 将用户排除清单转为规则测试，建立安全同步样本。
7. 评审P0结果并更新P1–P7估算，开始P1。

每个功能按“待分析 → 可实施 → 开发中 → 待验证 → 已验收”流转，阻塞单独记录。里程碑报告包括完成能力、适用平台、验证证据、未完成项和剩余估算；代码数量不作为进度。

当前实施状态见 roadmap.md 和 feature-matrix.md。计划中的功能需要逐项实现和验证，不因骨架完成而计为全功能交付。
