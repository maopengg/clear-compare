# Git 三方冲突：三方界面与原生边界

三方冲突页已接入 Git 变更面板和文件工作台。普通文本冲突可以查看基线/当前/传入版本，生成建议草稿、逐块选择来源或手动编辑，并在保存后单独标记该文件已解决。结果复用同一 CodeMirror 文件标签和缓冲区；普通 `⌘S`/`Ctrl+S` 只保存文件，页面按钮执行保存并标记已解决。特殊文件和跨平台原生验收仍未完成。

## 读取材料

`workspace_conflict_open` 接收仓库与冲突条目的原生 ID，重新读取状态后捕获该路径的索引阶段：1 为共同基础，2 为当前版本，3 为传入版本。返回各自对象 ID、文件模式和可读取的正文。新增/新增、修改/删除时某个阶段确实不存在，返回空的可选版本；不把它伪装成一个空文件对象。

普通文本返回现有工作文件对应的受保护编辑文档及三方自动合并建议。建议只在内存生成，不自动替换工作文件、不自动暂存。二进制、无法解码、超限或特殊模式保留明确的限制状态，不创建假的可编辑文本。每个 blob 原始输入最多 4 MiB、文本最多 30000 行，自动建议另受现有合并算法限制。工作文件不存在/为特殊类型时不自动创建或替换它。

索引版本、HEAD 和进行中操作的控制文件摘要随文档捕获。普通编辑保存入口也检查这份捕获，所以不能绕过冲突入口后继续保存一个过期结果。索引阶段被外部工具解决、合并中止或操作版本变化时，拒绝旧结果保存并保留已有未保存状态。重扫仓库保留打开文档及其冲突保护；关闭文档清除对应捕获。

## 保存与标记已解决

保存沿用文件工作台的文档 ID、编辑代数、编码/换行选项、文件身份复查、内容摘要、原始文件备份与写入流程。保存不会自动修改索引，保存与暂存失败分别保留真实状态。

`Action::ResolveConflict { document }` 只有打开过冲突并已保存的同仓库文档才能准备。它拒绝未保存内容、仍存在的冲突标记、外部改动后的文件以及失效冲突阶段。一次性计划执行前再次检查文件身份、保存摘要、索引阶段、操作状态和仓库状态，最终仅执行该路径的字面 `git add -- <path>`。其他未暂存改动不被一并提交或暂存。成功后该文档恢复为普通编辑文档；继续 merge/rebase 等仍使用已有的继续动作，不能把“暂存一个文件”说成整个操作已完成。

标记前在 common Git directory 的 `clear-compare-conflict-operations/<operation>/` 记录私有恢复材料：意图、完整索引副本、选中文件原始未合并记录、结果摘要及成功/失败记录，并为各阶段对象创建 `refs/clear-compare/conflicts/<operation>/stage-N`。索引副本上限 32 MiB。Unix 目录/文件使用 0700/0600；其他平台继承系统权限。锁冲突或 Git 失败不删除外部锁、不清除原冲突、不丢弃已保存工作文件，可检查现场后重新准备。

恢复材料是人工检查与后续恢复界面的基础，不是已完成的自动回滚入口。不能在索引后来已有其他改动时直接覆盖索引副本。暂存写入前的复查沿用现有 Git 操作模型，不声明能与任意外部 Git 写操作构成跨进程事务。

## 当前验证与剩余工作

七个临时仓库测试验证真实索引三方内容、合并建议、原始文件备份、只暂存选中文件、继续生成双亲合并提交、保存后继续编辑、未保存/标记/外部文件拒绝、外部索引解决/合并中止保护、阶段缺失、二进制限制、重扫保留、错误 ID/取消、CRLF 保存、索引锁失败/重试、恢复索引与对象引用。相关动作、文件编辑、逐行暂存回归 25 项通过；此前子模块等 Windows 路径回归另行记录。

三方页以一个未决差异块为单位呈现选择控件，避免为超长文件创建大量界面节点。整侧版本只写入编辑器缓冲区，不会立即覆盖工作文件；单块选取验证冲突来源标记，已手工改写的差异块不会被静默覆盖。合并建议同样显式应用，界面可撤销。
