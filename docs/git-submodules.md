# Git 子模块管理

仓库工具栏的“子模块管理”展示工作树 `.gitmodules` 与索引 Gitlink：名称、相对路径、嵌套层级、父项目记录的提交、实际 HEAD、本机注册状态和声明/注册/origin 地址。工作区仍未检出时显示“未初始化”；HEAD 与父项目记录不同、本地修改、版本冲突及配置问题分别展示。Git 地址中的标准 URL 凭据、查询与片段由原生层隐藏。

列表展开已初始化子模块中可读取的嵌套配置。尚未检出的父模块内部可能还有未知子模块，递归更新后刷新展示，不把初次列表当作完整的远端目录树。查询不下载对象；每次重新进入面板读取最新状态。按路径/名称/地址筛选，每页最多 200 条。查询失败保留原列表并显示错误，不循环重试；Git 拒绝读取的仓库状态（例如子模块路径变为符号链接）直接报告错误，不伪造成功列表。

## 初始化、更新与打开

- **初始化注册**：执行 Git `submodule init`，将地址等注册到本机配置，不检出文件、不下载对象。可以操作一个模块，或当前父项目的全部直接子模块。
- **更新**：执行 `submodule update --init --checkout --jobs=1`，初始化并检出父项目索引 Gitlink 所记录的提交。不会默认追随远程分支最新版本，不执行配置中的自定义 `!update` 命令，不调用 `--force`。
- **递归更新**：在上面的行为基础上递归初始化/更新下级子模块，包括执行过程中发现的尚未初始化模块。
- **打开仓库**：将已初始化的子模块作为独立仓库打开，可继续编辑、提交和进行 Git 操作。父项目和子模块按各自本地路径保存项目设置；新仓库条目与扫描范围会持久保留。

全部操作入口作用于完整模块列表，不受当前搜索和分页限制。单个嵌套模块在它自己的父仓库目录执行，确认区同时显示工作目录和 Git 参数。客户端传原生模块 ID，不把展示路径拼成磁盘写入目标。

## 复查与失败行为

所有写操作进入统一 Git 确认流程，使用一次性原生计划。确认后重查配置原文摘要、索引 Gitlink、模块 HEAD/状态、目录/Git 数据身份和缓存元数据。引用、配置、路径或实际修改变化后，需要刷新并重新确认。

更新前拒绝相关模块中未保存的编辑、非子模块文件的修改、未跟踪/忽略项及进行中的 Git 操作；已知递归子模块也纳入检查。Gitlink 版本差异本身允许更新，但版本冲突或无效配置需先处理。拒绝强制覆盖，不自动暂存、删除这些数据。父项目中未保存的编辑也应先处理。

更新沿用本机 Git、SSH、凭据、URL 重写等配置。网络调用有超时和输出限制，可能留下已注册配置、已下载对象、已完成的模块或部分克隆目录；应用不会重新发起失败写操作，也不自动移除这些目录。Git 自身的传输行为仍由 Git 管理。失败或取消后先刷新检查实际状态。

当前执行器的取消/超时分支只终止主 Git 进程，尚未完成辅助进程树的统一清理。尤其是递归更新，不能将取消返回视为所有 Git 辅助进程都已停止写入的保证；这一执行器缺口须优先修复并补运行中取消测试，不能据此验收完整的取消能力。

## 本机恢复材料

Git common directory 的 `clear-compare-submodule-operations/<operation>/` 保存原生意图、配置/HEAD 原文及校验摘要、计划的恢复引用、模块信息与命令成功/失败结果。新目录/文件在 Unix 上分别使用 0700/0600，其他平台继承系统权限。原始配置可能包含凭据，仅保存在本机恢复目录，不作为 Git 对象存储。

更新前为已初始化模块及本机缓存模块创建 `refs/clear-compare/submodules/<operation>/…` 引用。即使父模块已经撤销检出、缓存配置指向不存在的目录，也能保护缓存中的 detached HEAD 提交。缓存遍历只读取受限的模块管理目录，不扫描对象库文件内容。恢复引用保护 Git 对象，不是完整文件系统归档；缺少结果文件不能证明没有执行步骤。

成功结果或失败诊断提供恢复位置；备份阶段失败时，该位置可能只有部分材料。恢复管理界面尚未提供，手工恢复前须检查实际配置、目录、引用和执行结果。

## 当前边界

不提供强制清理、删除/撤销注册子模块、`--remote` 追随分支、URL 同步或编辑子模块定义的专用按钮；可打开 `.gitmodules` 使用文件编辑器。这些操作与完整冲突解决流程仍需后续完善，不能将本入口当作任意 Git 子模块命令的图形化替代。

管理需要工作树，裸仓库入口禁用。当前配置与 Git 写入路径要求 Unicode，路径不得逃逸到父级或 Git 元数据。子模块最多 4096 条、嵌套最多 32 层；配置快照有 32 MiB 上限，缓存目录遍历也有数量/深度限制，达到限制明确报错。真实原生窗口、SSH/凭据联调与 Windows/Linux 安装运行仍需分别验收。
