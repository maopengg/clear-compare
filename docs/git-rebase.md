# 交互式 Rebase

提交历史的右键菜单和选中提交工具栏提供入口。选中的提交作为固定基点，不改写基点本身；审阅列表按从旧到新的顺序列出其后至 HEAD 的普通提交。用户可以上移/下移、保留、修改完整说明、暂停编辑、Squash、Fixup 或丢弃。Squash 保留 Git 组合的说明；Fixup 丢弃该提交的说明。根提交改写和保留合并拓扑尚未提供。

预览列表使用稳定的提交 ID 保留输入与焦点。提交说明编辑保留原正文。准备计划失败时保留操作序列和输入；最终确认区域显示原生层校验后的序列、说明及恢复引用。

## 执行与恢复

- 仅接受已提交且无工作区变更的仓库状态，未保存的源码缓冲区也阻止执行。
- 原生层重新读取范围，要求每个候选提交恰好出现一次；拒绝重复、缺失、范围外提交和无前驱的 Squash/Fixup。当前范围最多 5000 个提交、审阅数据最多 8 MiB，超限明确失败。
- 执行前创建 `refs/clear-compare/backups/<operation>`。失败消息也提供该恢复引用；冲突和暂停保留 Git 当前状态。
- 显式关闭 autostash、update-refs、autosquash、fork-point 和 rebase-merges，保留空提交，避免用户 Git 配置改变已展示的操作范围。
- 序列编辑器只运行当前应用的内部模式，不调用用户配置的序列/消息编辑器。消息按原始提交身份选择，避免一次冲突导致后续说明错位。
- 受控计划保存在当前 worktree 的 `rebase-merge` 目录，暂停、冲突、应用重启之后继续/跳过仍使用同一份说明；完成或中止时由 Git 清理该目录。
- 继续和跳过前检查已执行与剩余序列是否仍匹配原计划；外部改变序列时拒绝执行。不能通过该入口增加 `exec` 等 shell 操作。
- “暂停编辑”之后可编辑文件、暂存、amend 当前提交，再继续。已有继续/跳过/中止入口处理后续 Git 状态。

## 验证

`cargo test -p clear-core --test workbench_rebase --locked` 是独立原生进程测试。测试程序同时提供内部编辑器子进程入口，实际调用 Git，覆盖排序/修改说明/丢弃、Squash/Fixup、恢复引用、暂停继续、冲突继续、跳过后修改说明、worktree 隔离、外部改动序列拒绝，以及带空格/单引号/中文的执行程序路径。所有写操作均使用临时仓库。

`scripts/check-git-history.cjs` 使用真实 WASM 页面和模拟 IPC，覆盖序列编辑、重排后的输入保留、焦点陷阱、准备失败保留、原生计划展示和确认前不写入。该检查不替代原生 Git 操作或三个系统的安装验收。

完整 Git 客户端目标仍未全部完成；根提交和合并拓扑改写、历史编辑快捷入口、完整恢复界面及三端安装验收继续追踪在功能清单中。
