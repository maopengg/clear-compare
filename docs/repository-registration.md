# 手动收录与重新定位仓库

首页“添加仓库”接受一个已有 Git 仓库根目录，可以输入绝对路径或使用系统目录选择器。先“检查仓库”展示规范位置、当前分支和远程匹配标识，再确认收录。这个流程不克隆、不初始化、不移动或改写仓库；它只保存工作台目录。手动收录与扫描根目录独立，最多 256 个，重启和重新扫描后保留；手动项只检查自身，不递归发现内部的仓库。普通、裸仓库、有效的 worktree/子模块沿用统一原生识别。

每条仓库记录有“管理”入口，可以移除收录，或指定移动后的新位置。重新定位只适用于原位置已经无法读取的仓库；原位置仍可访问时应单独添加另一个副本。打开的源文件标签须先关闭，包括未修改标签，避免把旧原生文件 ID/草稿错误绑定到新仓库。

检查生成一次性原生计划；确认时重新读取规范路径、根目录/Git 目录身份、Git 共享目录和远程标识，并检查旧记录及新位置现有记录是否变化。仓库类型必须相同。远程标识与原记录不同会明确提示，由用户核对；没有远程的本地仓库也可明确选择重新定位，不凭目录名称自动合并。

确认后，收藏取两条记录的并集，最近打开时间取较新值；旧记录已有的文件规则/搜索偏好、收藏/最近分支优先转移。若新位置已经被重新扫描发现，则把两条记录合并成一条，检查区提示旧规则优先；原记录未设置的偏好保留新位置现有值。旧位置加入移除收录集合，后续扫描不重新生成旧记录；新位置作为手动项保留。

收录、重新定位及桌面入口的移除操作，均先原子保存工作台配置，成功后更新内存；保存失败保留原目录记录和偏好。失败后输入保留，已消费/失败的确认计划须重新检查。修改路径会撤掉旧检查区，Esc/关闭返回入口焦点；原入口被移除时回到添加入口。检查区位于首页工具栏下，保持主内容可见，可滚动并有高度上限。

原生测试使用临时仓库验证持久化、单仓库发现、重扫、重定位/合并、源标签、取消、过期/替换身份、远程变化、失败回滚、裸仓库、路径别名及重新收录。`scripts/check-repository-registration.cjs` 使用真实 WASM 和模拟 IPC 验证界面检查/确认分离、原生 ID、取消/焦点、失败保留、目录选择和双语紧凑布局；模拟 IPC 不代表真实原生窗口或跨平台安装验收。

这里仍不包含克隆/初始化仓库、手动远程匹配分组、更名已有比较项目目录或迁移 Git 文件。原位置可读时不提供“合并两个不同副本”捷径。
