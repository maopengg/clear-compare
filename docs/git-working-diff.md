# Git 工作区差异与选择暂存

工作区将文件分成未暂存、已暂存、未跟踪和冲突四组。同一文件同时有已暂存和未暂存修改时，会分别出现在两组；这不是重复的磁盘文件。路径筛选和分组筛选在分页之前执行，列表每页最多 200 个不同条目，支持平面/目录树及多选。整文件操作沿用原生 Git 计划与状态复查；最多选择 10000 个文件。

点击文件打开右侧差异，三个区域分别是：

- 未暂存：暂存区（索引）与磁盘工作区之间的差异。
- 已暂存：当前提交 HEAD 与暂存区之间的差异。
- HEAD 对工作区：包含已暂存和未暂存修改的只读总览。

普通 UTF-8 文本的未暂存/已暂存区域提供“暂存此块／取消暂存此块”和选中行操作。替换通常由删除行和新增行组成，可选择两行一起处理；仅选择删除或新增表示独立删除或插入。连续替换区按旧、新行的顺序对应，未选中的修改留在原区域。文件末尾缺少换行会明确标识，普通 LF 不逐行显示。

部分暂存只改暂存区，不保存或改写磁盘工作文件。权限模式变化不随文本块一起暂存，需要使用整文件操作；新文件则保留其文件模式。新文件和删除文件也支持部分处理，产生的暂存区内容可能因此仍是普通文件。Git 的 CRLF/属性规则仍由 Git 差异和 `git apply --cached` 处理，不通过编辑器的换行转换代替。

当前重命名、冲突、二进制、链接和子模块差异使用原始只读预览及适用的整文件操作；三方冲突编辑仍待完成。未跟踪目录尚需到文件工作台展开后选取具体文件。只读总览不能直接用于部分暂存。

## 一致性与失败处理

每份差异有原生生成的标识、所属仓库和状态版本。行和块标识只能引用当前捕获中的内容；客户端不能提交任意补丁或文件路径。准备时运行 Git 的补丁检查，执行前复查仓库版本并重新读取所选文件差异、比较内容摘要，因此恢复相同大小和修改时间也不能绕过内容检查。未保存的源编辑缓冲区会阻止相关 Git 写操作，执行阶段会再检查一次。

成功后刷新状态和当前差异；失败保留文件筛选、选择及原差异，不自动重试写操作。重新加载失败也保留旧差异且不循环重试。外部仓库版本变化后的旧差异不能继续操作，需要刷新和重新选择。变更文件可通过原生条目转换直接打开文件编辑器；切回 Git 保留当前差异和选择，源编辑标签仍独立保留。

选择暂存前保留恢复引用：通常指向操作前暂存区的文件对象；没有旧文件对象时可能指向 HEAD，新仓库首个新增文件不会创建空引用。这不是整个工作区备份，当前没有该引用的图形恢复入口。备份引用显示在操作日志中，不混入普通分支和标签列表。

## 限制与验收

单文件补丁最多 4 MiB、50000 行；预览每页 500 行，超长行只显示前 8192 个字符并注明操作包含完整行。跨页行选择保留，但更换差异快照会清空旧行选择。当前同时捕获一份工作区差异；Git 子进程另有超时和输出上限。非 Unicode 路径的 Git 写操作尚未支持。

原生测试用临时仓库检查实际索引内容、磁盘内容、恢复对象、部分新增/删除、选中替换、CRLF/缺少末尾换行、权限分离、字面路径、分页及外部变化。浏览器测试使用实际界面与模拟 IPC 检查交互，两者不替代三系统的原生安装运行验收。
