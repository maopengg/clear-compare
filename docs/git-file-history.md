# 文件历史与逐行追溯

入口包括源编辑器工具栏、源文件右键菜单，以及历史版本阅读器的“历史追溯”。它们打开同一个紧凑页面：左侧提交列表，主区域切换逐行追溯和历史正文。回到原视图保留源文件目录/滚动与未保存草稿，不保存、不检出、不暂存文件。

## 固定范围与重命名

源文件入口捕获当时实际 HEAD；历史阅读器入口使用它已经固定的提交。查询只接受原生仓库、文件、目录会话 ID，不能从 UI 拼接路径。仓库没有提交或文件不在该提交中时，明确显示状态，不把空结果解释为该文件内容相同或来源未知。

文件历史使用 Git log --follow -M，依据 Git 的重命名检测向前追踪。每条记录保存原生文件名、提交身份、该版本路径和重命名前路径。引用移动或工作区文件被修改后，仍查看打开时的提交历史。保留原有 Git 对合并历史/路径简化的语义；不声称跨重建、所有复制或任意历史重写都能精确识别同一文件。

历史最多捕获 5000 个提交，每页 100 项；达到提交上限显示截断。每条 Git 命令有 30 秒、16 MiB 输出预算。浅克隆明确提示历史可能不完整。固定并复查 shallow 和 info/grafts 内容摘要（各最多 1 MiB）；边界元数据变化后旧会话失效，须重新打开。根目录、Git 管理目录及共享目录映射变化也拒绝继续，避免从另一个仓库读取同名对象。

## 行归属与原始版本

逐行追溯按固定提交运行 Git blame --line-porcelain，不会把磁盘改动或未保存草稿作为已提交内容。原生层先读取并重新校验该提交的 Git blob 身份，再核对返回的每行字节、顺序和数量。页面展示提交、作者、UTC 日期、Git 物理行号及正文，原始时区、说明、旧文件名和原始行号可查看。根提交/浅克隆等追溯边界有独立提示。

每页 200 行。选择一行后，“查看所选版本”使用该行的原生 ID 打开原始提交和原始文件名，并定位原始行；不会把界面显示路径回传为文件操作参数。“查看提交详情”和每行的提交按钮打开对应仓库的提交详情；即便来源编辑标签属于另一个仓库，也使用正确的仓库 ID。返回编辑器保留已有标签和草稿。

行追溯当前支持最多 4 MiB 的 UTF-8 普通文件、100000 个以 LF 分隔的 Git 物理行。保留 CRLF 字节核对，显示正文时移除行末 CR；UTF-8 BOM 只在第一行隐藏首个标记。无最终换行、空文本、SHA-1/SHA-256 仓库均有独立验证。超长行显示前 8192 字符并提示。二进制、UTF-16、链接及超限文件明确拒绝行追溯，仍可查看提交历史或通过原有历史正文/十六进制阅读器查看版本。

## 读取、取消与会话

已有正文在新查询、失败或取消期间保留，底部显示读取状态与取消入口。失败不生成虚假的空内容/未提交行，不触发源文件保存。历史列表分页、删除项禁用、原文/十六进制分页和选择状态分开管理；切换列表页不会使已选删除项突然变成可读取版本。

历史阅读会话保留在本进程内，最多四组，每组缓存最多两个受限文本对象和 4000 个行定位目标。当前文件历史保护它的原始版本阅读器，连续查看多个版本不会回收入口会话；同一仓库/提交复用树。返回原视图、进入提交详情或替换追溯来源时释放旧历史，移除定位目标和缓存，不修改仓库。更早行目标被回收时要求重新读取该页。

正文复用固定版本阅读器：文本 500 行/页，较大或二进制对象十六进制 4096 字节/页，读取与缓存上限见 [提交文件浏览](git-revisions.md)。原始行位于后续文本页时先识别格式再定位，避免把文本行偏移当成二进制字节偏移。

## 验证与剩余范围

原生临时仓库测试覆盖跨重命名、旧文件名/原始行跳转、固定锚点、真实 CRLF 行字节/作者、无提交/未跟踪、历史文件入口、列表与行分页、长行/空文件/BOM/无最终换行、错误 ID/取消/仓库替换、浅克隆及边界变化、裸仓库、Unicode/控制字符与字面路径、链接、SHA-256、关联工作区共享目录重定向，以及多版本访问后的入口保留与关闭释放。私有解析测试检查 Git C 引号与高位 UTF-8 八进制转义，避免路径解码溢出。

scripts/check-file-trace.cjs 使用真实 WASM/CodeMirror 与模拟 IPC，检查三个入口、原生 ID、分页、行定位、格式切换、取消/错误保留、删除项状态、源目录不重载/草稿保留、正确提交导航、释放会话、未跟踪/浅克隆/截断提示、双语和 900/1440 布局。原生 Git 和磁盘行为由 Rust 测试单独证明，模拟 IPC 不代表原生窗口或跨系统安装验收。

未保存/暂存内容追溯、UTF-16/其他编码的行映射、复制/移动行的高级检测选项、跨重启恢复阅读会话、历史搜索筛选及完整三系统交互验收仍待完善；不能将这一批作为完整 Git 客户端完成的证据。
