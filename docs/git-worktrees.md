# 关联工作区（Worktree）

仓库工具栏的“工作区管理”展示 Git 已注册的主工作区、关联工作区、裸仓库、分支/提交、分离 HEAD、锁定与失效记录。列表按路径/分支筛选，每页最多 200 条；操作用原生捕获的条目标识，不从显示路径重建目标。查询失败保留上一列表，不循环重试。

## 创建与打开

选择系统目录对话框中的父目录，再输入一个新文件夹名称。支持：

- 从 HEAD、本地分支、远程跟踪分支或标签创建一个新分支并检出。
- 检出未被其他工作区占用的已有本地分支。
- 按捕获的提交创建分离 HEAD 工作区。

分支菜单的“从此版本创建工作区…”预选对应引用。创建先展示 Git 命令，执行时重查仓库版本、注册记录、父目录身份和目标不存在，并独占预留新目录。不会强制占用已经检出的分支，也不覆盖同名目录。失败保留表单、日志和可能存在的已预留/部分创建目录，不自动清理外部文件；请先刷新查看实际状态。

“打开”将选中的工作区作为独立仓库载入工作台，与原仓库共享远程匹配和 Git common directory，文件规则与编辑标签仍按本地路径分别管理。位于现有扫描范围之外的工作区作为单独扫描根保留，重启和重新扫描后仍可找到。“系统中显示”打开对应系统文件管理器；具体 macOS/Windows/Linux 集成仍需分别实测。

## 锁定、移除与清理

锁定说明可自定义；锁定/解锁使用统一确认流程。主工作区和当前选中的工作区不提供关联工作区移除/锁定入口。

移除会删除对应的关联工作区目录，但不删除分支；先保存其 HEAD 的恢复引用并写入本机操作记录。仅对 Git 判定干净、没有未跟踪或忽略文件、没有打开编辑标签且未锁定的工作区开放移除。执行前再次检查注册记录、目录身份、Git 归属及文件状态；不调用 `--force`。Git 自身拒绝的状态（例如含已初始化子模块的工作区）保留错误与现场。成功后同时移除首页仓库条目与该路径的独立扫描根，项目规则保留。

“清理失效记录”使用 `git worktree prune --expire now --verbose`。界面显示可清理条目数量，执行前确认，注册记录发生变化则必须重新检查。清理仅删除失效的 Git 注册信息，现存目录与已锁定记录保留；对可清理记录中的提交先创建恢复引用，避免仅由 detached HEAD 保留的提交因此失去引用。

## 本机恢复材料与限制

Git common directory 下的 `clear-compare-worktree-operations/<operation>/` 保存：

- `registrations.bin`：操作前的原始 NUL 分隔工作区注册列表。
- `before.json`：操作参数、注册快照摘要、清理恢复引用位置等。
- 创建时的 `reserved.json`：原生目标路径和预留目录身份。
- `result.json`：命令成功/失败；缺失结果不能推断命令没有执行。

移除的提交恢复引用通过操作确认与结果日志展示；清理的引用位于 `refs/clear-compare/worktrees/<operation>/`。这些引用保护 Git 对象，不是包含未跟踪文件、忽略文件或所有文件系统元数据的归档。恢复管理界面尚待开发，手工恢复前需检查实际目录、注册和引用状态。

恢复目录在 Unix 新建时使用 0700、文件使用 0600；其他平台继承系统权限。创建、锁定、移除与清理都使用一次性原生计划；取消或失败不自动重复写操作。目录与注册状态仍可能被外部 Git 进程改变，刷新失败时不会把旧列表假装成最新结果。

每个仓库最多列出 4096 个注册工作区；Git 命令有时间和输出上限。非 Unicode 路径可显示其本地条目，但当前 Git 写入/目录选择要求 Unicode 路径。裸仓库可列出并创建关联工作区，空仓库没有可检出的提交时明确报错。移动现有 Worktree、修复手工搬迁的注册、强制移除有修改的目录，以及恢复材料的图形化管理不在当前入口中。
