## Multi-project Git workbench (in development)

Implemented foundation: persisted multi-root discovery, repository/worktree/submodule/bare recognition, normalized remote identities, home search/favorites/recent entries, status/references/remotes, typed one-use mutation plans, whole-file stage/unstage, commit/amend, branch/revision actions, fetch/pull/push, stash save, operation continue/skip/abort and recovery references. Advanced core operations are not all exposed in the interface.

History foundation: paged commit graph and reference/author/date/path/message/hash filters, pinned commit details and merge-parent selection, captured file IDs for bounded/paged read-only patches, parent navigation and contextual copy/cherry-pick/revert/checkout/reset/branch/tag actions.

The workbench also exposes ordinary-text hunk/line staging, reference/index/working-tree comparison, paged stash management, independent fetch/push remote configuration, read-only connection checks, and Worktree creation/open/reveal/lock/unlock/protected removal/pruning. Submodule management adds recursive status, local registration, pinned checkout/update, recursive initialization/update and opening module repositories, with configuration and HEAD recovery material. Source browsing provides multi-tab CodeMirror editing and grouped cross-repository name/path/content search. These entries have temporary-repository and mocked-IPC UI evidence; they are not complete native desktop or cross-platform acceptance. See the scoped documents linked from the acceptance log for limitations.

Not complete: full history tree browsing, patch export/apply, special-diff partial staging, interactive rebase, integrated three-way conflict resolution, advanced submodule maintenance, unrestricted remote configuration/recovery GUI, cross-file replacement, general non-Git source roots, and complete platform integration. Track all requirements in [workbench acceptance](workbench-acceptance.md); do not equate this foundation with the complete Git client.
